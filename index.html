Find the breakpoint before production does.

breakpoint is an interactive, quantitatively honest system-design sandbox. Compose an architecture on a canvas, run a traffic scenario, and watch real queueing-theory metrics — utilization, latency percentiles, drop rate, retry amplification — propagate through the graph in real time.

$ cd breakpoint && npm install

// the point

Watch what happens when you change one thing.

Every number is emergent from editing the running graph — there are no scripted demos. Drag a node, flip a parameter, fire a spike; the whole system re-solves instantly.

delete the load balancer the remaining server's ρ climbs toward 1, the latency curve goes vertical, drops start, the node turns red.
add API replicas offered load splits across instances, ρ falls, p99 recovers — live.
remove the cache miss ratio → 100%, database arrival rate jumps 5–10×, the DB becomes the bottleneck.
fire a flash spike retries push λ_eff > λ; the amplification and the recovery time are both measured.
shard a hot table per-shard load shows on sub-cards; a hot shard under a Zipfian key distribution is flagged.
ask "how many users until this breaks?" the system grade answers it: A–F, a headroom multiple, and "breaks around N".
// credibility

Every number is computed twice.

A visualizer is only worth trusting if the math is real. breakpoint runs two independent engines and checks that they agree — in CI, on every commit.

closed form

Analytical solver

M/M/1, M/M/c (Erlang C), M/M/c/K bounded queues, Erlang B/C, plus Jackson-network flow equations for per-node arrival rates, retry fixed-point iteration, and critical-path latency. Runs on every edit, instantly.

seeded

Discrete-event simulation

A binary-heap event queue, non-homogeneous Poisson arrivals, per-request routing with fan-out / join, log-spaced latency histograms. Same seed + same design ⇒ identical run.

analytical ≈ simulation — within tolerance for stationary load, asserted as a test.

Every formula module ships a matching *.test.ts that asserts against textbook values — e.g. M/M/1 with λ=8, μ=10 → ρ=0.8, L=4, W=0.5.

// in the box

Enough to model a real system.

components

Load balancer, API server (vCPU/RAM sizing, bounded queue, load shedding, autoscaling), cache, SQL database, queue, worker, CDN, object store, third-party service.

db topologies

Single, primary + read replicas, multi-primary, sharded — each instance's load rendered on its own sub-card, with hot-shard detection.

load models

Closed-loop (N concurrent users + think time, via the interactive response-time law) or open-loop (target RPS). Constant, ramp, diurnal, spike.

bottleneck detector

Re-solves patched versions of your design to rank the cheapest fix that clears the SLO — one click to apply it.

explain everything

Hover any metric or control for the formula behind it and the dominant term. It's a teaching aid as much as a sizing tool.

share & export

Design compressed into a URL, JSON import / export, canvas PNG / SVG, and a markdown metrics report. A random-system generator for practice.

// contribute

Built to be read and extended.

The engine has no React imports anywhere — it's pure and testable. A new component is one file in src/engine/components/, one registry entry, one docs paragraph; the node UI and the schema-driven inspector form are generic. Presets and guided challenges are just data.
